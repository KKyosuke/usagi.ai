# ドキュメント執筆ガイドライン

`usagi.ai` のドキュメント（`doc/` ディレクトリ配下）を追加・編集する際のルールとガイドラインです。
ドキュメントの一貫性と可読性を保つため、本ガイドラインに沿って執筆をお願いします。

## 📁 1. ディレクトリ構成と配置ルール

`doc/` ディレクトリは、ターミナルから実行する **CLI** と、`usagi hop` で起動する **APP (TUI)** の2大カテゴリに分かれています。

### `cli/` - コマンドラインツール
ターミナルから直接実行する CLI コマンドに関するドキュメントはここに配置します。
- 例: `usagi init`, `usagi hop`, `usagi doctor`

### `app/` - TUI アプリケーション
起動したあとの TUI アプリケーション内部に関するドキュメントは、さらに細分化して `app/` 配下に配置します。
- **`app/tui/`**: TUI の内部コマンドモードから実行するコマンド（`session`, `ai`, `space` など）。
- **`app/architecture/`**: システムの内部設計、コード構成、グローバルなデータ管理など、開発者向けドキュメント。
- **`app/ui/`**: UIのレイアウト、画面遷移、モードの種類など、画面の振る舞いに関するドキュメント。
- **`app/project/`**: 初期化後のディレクトリ構造や設定ファイル仕様など、プロジェクトに関するドキュメント。

新しいカテゴリが必要になった場合は、チームで相談の上、`doc/README.md` の目次に追記してください。

## 📝 2. フォーマットと記述ルール

### マークダウンの基本
- 見出しのレベルは厳守してください。タイトルは `#`、大セクションは `##`、小セクションは `###` とします。
- コードブロックには言語指定を必ず含めてください（`bash`, `json`, `rust`, `text` など）。

### インラインの強調と引用
- コマンド名、ファイルパス、変数名、キーボードのキーなどはバッククォート（`` ` ``）で囲んでください。
  - ⭕️ 正: `` `usagi.config` を編集します。 ``
  - ❌ 誤: `usagi.config を編集します。`
- 重要な注意点やヒントは、GitHub の Alert 記法（`> [!NOTE]`, `> [!WARNING]`, `> [!TIP]`）を使用して目立たせてください。

### 図解（Mermaid）の活用
フローチャートや構造図、シーケンス図など、視覚的に説明したほうが分かりやすいものは `mermaid` 記法を積極的に活用してください。

### 関連ドキュメントへのリンク
ドキュメントの末尾には必ず `## 関連ドキュメント` セクションを設け、関連する他のドキュメントへの相対リンクをリスト形式で記述してください。

```markdown
## 関連ドキュメント

- [初期化後のディレクトリ構造](../project/directory.md)
- [`usagi init` コマンド](../../cli/init.md)
```

## 🗣️ 3. 文体・用語の統一

### 文体
- **「です・ます」調** で統一してください。
  - ⭕️ 正: 「このコマンドはリポジトリを初期化します。」
  - ❌ 誤: 「このコマンドはリポジトリを初期化する。」

### 用語
既存のドキュメントと一貫性を持たせるため、以下の用語ルールに従ってください。

- **worktree / ワークツリー**: 英単語の `worktree` を使用してください。（例: 「worktree を作成します」）
- **TUI**: ターミナル・ユーザー・インターフェースの略称として `TUI` を使用します。
- **コマンドモード / サイドメニューモード**: モード名はカタカナ表記で統一してください。（詳細は [モードの種類と切り替え](../app/ui/mode.md) 参照）
